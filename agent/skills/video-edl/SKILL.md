# Video EDL — Edit Decision List

<!-- Mandatory triggers: построй план монтажа, EDL, plan cuts, что вырезать, список срезов -->

Фаза 1.5: ты принимаешь результат анализа и строишь точный план монтажа.
LLM решает — mcp-video исполняет. Никогда не наоборот.

## Вход

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| `analysis-map.json` | Результат video-analyze (обязателен) | — |
| `target_duration_sec` | Желаемая длина в секундах | 300 |
| `target_format` | `16:9` / `9:16` / `1:1` | `16:9` |
| `content_type` | `highlight` / `lesson` / `shorts` / `podcast` | `highlight` |
| `platform` | youtube / shorts / reels / tiktok | youtube |

Если `analysis-map.json` не существует — сказать: «Сначала запусти video-analyze для получения карты моментов».

## Шаги

### Шаг 1: Загрузка схемы и стиля

Прочитай:
- `../../knowledge/edl-schema.md` — схема EDL и алгоритм трансляции
- `../../soul.md` — настройки темпа и стиля (дефолты если не заполнен)

### Шаг 1.5: ПЛАН НАСЫЩЕНИЯ (saturation-plan.md)

**До построения EDL** — агент заполняет шаблон `knowledge/saturation-plan.md`.

Что заполняется:
1. Структура глав (по транскрипту) — якорные фразы + ориентировочные тайм-коды
2. **ui_critical диапазоны** — вручную размечаются участки footage где зритель должен видеть непрерывный экран/действие. Формат:
   ```
   ## ui_critical
   - "открываем настройки VPN": 45.0–62.0
   - "вводим данные сервера": 120.0–145.5
   ```
3. Full-screen сцены (Interstitial) — когда/какой variant, ТОЛЬКО между шагами.
   **ПРАВИЛО:** каждый interstitial (6 сек) → в EDL помечается скучный footage-кусок
   той же длины на вырез или ускорение x4. Interstitial не добавляет к хронометражу.
4. Оверлеи — список с anchor_phrase
5. KineticText — список ключевых слов (≥1 на 60 сек), включая факты NOT озвученные вслух
   (цены, шаги, параметры из UI — добавляются как информационные плашки)
6. ffmpeg-эффекты — xfade переходы, colorgrade, zoompan (обязательный минимум)

**[CHECKPOINT 1 — СИНХРОННЫЙ]** — показать saturation-plan.md владельцу, дождаться явного ОК.
Без ОК — не рендерить ничего (ни отбивки, ни EDL, ни оверлеи).

Что проверяется при checkpoint:
- **Целевая длина ≤ 80% исходника** — без этого план не проходит
- Запланированных событий ≥ (финальная длина сек / 18) — плотность 1/18 сек
- Нет gaps >18 сек без события
- Все главы покрыты ProgressStepper + ChapterWipe
- ui_critical диапазоны размечены (даже если пустые — явно указать "нет ui_critical")
- Отбивки ТОЛЬКО между шагами, ≤3 штуки, каждая ≤7 сек
- Для каждой отбивки — footage-эквивалент помечен на вырез в EDL

### Шаг 2: Разбор analysis-map.json

Из карты извлечь:
1. Все сегменты с `score >= highlight_threshold` (дефолт 6) → кандидаты на `keep: true`
2. Все `silence_intervals` → в поле `silence_remove`
3. Сегменты с типом «набор текста без комментариев» >10 сек → в `speed_segments` (x4)

Для `content_type: shorts` — порог score поднять до `shorts_threshold` (дефолт 8 из soul.md).

### Шаг 2.5: Планирование overlay — плотность и якоря

Перед построением EDL — составить список overlay с anchor_phrase:

**Правило плотности:** ≥1 визуальное событие / 12-18 сек финала.
Для 7-минутного видео = минимум 23 события. Сквозные (ProgressStepper, CountUpTimer) не считаются.

**Обязательные overlay для технических туториалов:**
- KineticText на каждый смысловой блок (числа, топонимы, инструменты, выводы): ≥7 штук на 7 мин
- Ken Burns / punch-in: на каждой говорящей голове ≥10 сек
- ChapterWipe: на каждой главе (смена темы)
- ProgressStepper: отдельный рендер с правильным activeStep на КАЖДУЮ главу

Каждый overlay в EDL должен содержать поле `anchor_phrase`:
```json
{
  "overlays": [
    {
      "component": "KineticText",
      "anchor_phrase": "нидерланды польша",
      "duration_sec": 3,
      "offset_sec": 0,
      "props": { "text": "НИДЕРЛАНДЫ / ПОЛЬША", "highlight": "нидерланды" }
    }
  ]
}
```

Тайм-коды НЕ задаются на этом этапе — они вычисляются после нарезки через `anchor-overlays.mjs`.

### Шаг 3: Построение EDL

Собрать `edl.json` по схеме из `edl-schema.md`:

```json
{
  "source": "{source_file}",
  "target_duration_sec": {N},
  "target_format": "{format}",
  "created_at": "{ISO datetime}",
  "segments": [...],
  "silence_remove": [...],
  "speed_segments": [...]
}
```

Правила при построении:
- Минимальная длина сегмента: 3 сек
- Margin ±0.3 сек уже включать в `start_sec`/`end_sec`
- Если суммарная длина `keep: true` > `target_duration_sec * 1.2` → повысить порог score или уменьшить длинные сегменты
- Для `content_type: shorts` — первый сегмент ОБЯЗАТЕЛЬНО тип `hook`

### Шаг 4: Self-eval loop

Оцени EDL по 3 осям (0.0–1.0 каждая):

**Adherence** — соответствие запросу:
- Хронометраж в ±15% от `target_duration_sec`? (+0.5)
- Формат указан корректно? (+0.3)
- Контент-тип соблюдён (lesson/highlight/shorts)? (+0.2)

**Pacing** — темп монтажа:
- Нет подряд идущих сегментов score <5 суммарно >30 сек? (+0.5)
- Каждый переход между сегментами имеет мотивацию? (+0.3)
- Нет сегментов длиннее 120 сек подряд без смены типа? (+0.2)

**Virality** — для shorts/reels (для остальных: 1.0 автоматически):
- Первый сегмент = hook, score = 10? (+0.5)
- ≥1 сегмент типа `opinion_bomb` или `revelation`? (+0.3)
- Итоговая длина ≤ 60 сек (для Shorts)? (+0.2)

**Порог:** сумма < 1.5 → пересмотреть EDL (retry). Максимум 2 попытки.

После 2 неудачных попыток — показать владельцу с пометкой «что не удалось исправить».

### Шаг 5: Human checkpoint

Показать владельцу human-readable план и получить ОК перед передачей в video-cut.

## Формат вывода

### Файл: `edl.json`

Сохранить рядом с `analysis-map.json` (или в `/tmp/edl/edl.json`).

### Human-readable план

```
=== ПЛАН МОНТАЖА (EDL) ===
Источник: input.mp4 (40:12)
Цель: 5:00 | Формат: 16:9 | Тип: highlight

Сегменты к сохранению (8):
  #1  [00:15–01:30] score=10 hook      "Смотрите, AI Office запустился"
  #3  [02:15–03:40] score=9  insight   "Ключевой момент — вот почему..."
  #5  [07:20–08:45] score=8  problem   "Ошибка! Сейчас починим"
  #7  [15:00–16:20] score=8  result    "Готово, всё работает"
  #9  [22:30–23:15] score=7  insight   "Итог урока"
  (ещё 3 сегмента)

Тишина к удалению: 12:45 (23 интервала)
Ускорение x4: 2 части (набор текста, суммарно 4:30 → 1:07)

Self-eval: Adherence 1.0 / Pacing 0.9 / Virality 1.0 → PASS (2.9/3.0)

Согласуешь план? Или скорректировать порог/хронометраж?
```

## Ошибки и восстановление

- `analysis-map.json` отсутствует → «Запусти сначала video-analyze»
- Суммарная длина keep-сегментов << target → снизить порог score на 1 пункт, retry
- Хук не найден в первых 30% видео (для shorts) → сообщить владельцу, предложить использовать лучший момент из любого места
- После 2 retry self-eval < 1.5 → показать план с пометкой недостатков, пусть владелец решает
